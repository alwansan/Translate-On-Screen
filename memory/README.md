# Project memory · ذاكرة المشروع

هذه الذاكرة جزء من المصدر وتُزامن إلى GitHub مع كل دفعة متحققة. لا تعتمد على بقاء المحادثة أو مجلد scratch.

## ترتيب الاستعادة

1. `prompt/RESTORE_SESSION_AR.md`: نقطة الدخول المختصرة والهدف الحالي.
2. `memory/PROJECT_MEMORY_AR.md`: طلبات المالك والقرارات المستقرة.
3. `memory/STATE.json`: الإصدار والرؤوس والأدلة وحالة الدفعة.
4. `docs/PLAN_AR.md`: الميزات ومراحل الإكمال ومعايير القبول.
5. `memory/evidence/` و`docs/VALIDATION.md`: أدلة الملفات والبناء والتشغيل.
6. `memory/sessions/`: سجل الدفعات؛ لا تجعل رسالة الاستعادة أرشيفاً متنامياً لكل التفاصيل.

## قواعد التحديث

- قبل التنفيذ: تحقق من رأس فرع العمل وملاحظات المالك؛ لا تعِد تجربة ناجحة دون سبب جديد.
- أثناء التنفيذ الطويل: دوّن checkpoint واضحاً؛ العمل غير المبني يظل غير متحقق.
- بعد الدفعة: سجل commit الكود وCI والفحوص وحدودها، وحدث الخطة والمشكلات ورسالة الاستعادة، ثم ادفعها إلى الفرع نفسه.
- فرق بين تصريح المالك عن تجربة هاتف، واختبار محاكي، وفحص ساكن، وunit test. لا ترفع أحدها إلى مرتبة الآخر.
- معرفات Library في فهرس الأدلة هي طرق استرجاع دائمة؛ مسارات scratch نسخ عمل قابلة للاختفاء. لا تطلب إعادة رفع ملف قبل محاولة استرجاعه بالمعرف.
- لا تضع مفاتيح API أو نصوص شاشات المستخدم أو نسخاً من التطبيق المرجعي في سجل الاختبار أو commits الجديدة.
